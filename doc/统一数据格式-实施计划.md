# 第一步：统一数据格式 — 实施计划（修订版）

## 设计原则

用户决策：
1. **从头重写**：不恢复 `.pyc`，基于算法文档重新设计最优数据结构
2. **工具函数提取**：将 chordal 距离等公共函数移到统一位置（`gbz_types.py`）
3. **整体重构**：不只是加转换层，而是修改两个模块内部使其原生输出统一格式

## 核心设计：连通子集抽象

### 类型层次

```
ConnectedSubset (ABC / Protocol)
├── PointSubset (0D) — 孤立 GBZ 点
│   数据：(E, beta1, beta2) 三元组
│   来源：原 is_continuum == False
│
└── LineSubset (1D) — 连续简并线段
    数据：(E, mu1, theta1_start, theta1_end, beta2_arr)
    来源：原 is_continuum == True
```

### 选型：dataclass + Union vs ABC 继承

| 方案 | 优点 | 缺点 |
|---|---|---|
| ABC 继承 `class PointSubset(ConnectedSubset)` | 类型安全，`isinstance` 自然，可加抽象方法 | Python 中 over-engineered |
| **dataclass + Union** `ConnectedSubset = PointSubset \| LineSubset` | 简洁，与现有 `.pyc` 设计一致，`match/case` 友好 | 无编译期类型检查 |

**推荐**：dataclass + Union。Python 3.9+ 的 `Union` 配合 `isinstance` / `match/case` 已经足够清晰。算法文档也指出"对于 2D GBZ 问题，只有两个类别"，不需要复杂的继承树。

### 数据类详细设计

```python
# gbz_types.py

@dataclass(frozen=True)
class PointSubset:
    """0D 连通子集：孤立 GBZ 点。"""
    E: complex
    beta1: complex       # = exp(mu1 + i*theta1)
    beta2: complex       # 代表性 beta2 值

    @property
    def mu1(self) -> float:
        return math.log(abs(self.beta1))

    @property
    def theta1(self) -> float:
        return math.atan2(self.beta1.imag, self.beta1.real) % (2 * math.pi)

    def as_triplet(self) -> tuple[complex, complex, complex]:
        """转为 (E, k1, k2) 三元组，k1 = -i*log(beta1), k2 = -i*log(beta2)"""
        ...


@dataclass
class LineSubset:
    """1D 连通子集：连续简并线段。

    beta2_arr 为 lazy-load：创建时不填充，需要时调用 fill_beta2()。
    形状 (N, 2)，存储区间内每个 theta1 点对应的两个边界 beta2 根。
    """
    E: complex
    mu1: float
    theta1_start: float
    theta1_end: float
    beta2_arr: Optional[np.ndarray] = None  # lazy, shape (N, 2)

    # 以下字段用于计算 beta2_arr，存储但不暴露
    _M: int = 0
    _N: int = 0
    _poly_diff: Any = None  # PolyDiffContext, 用于 lazy fill

    @property
    def theta1_width(self) -> float:
        """区间宽度（弧度），正确处理 2π 环绕。"""
        ...

    @property
    def left_endpoint(self) -> tuple[complex, complex]:
        """(beta1_left, beta2_left) 左端点。需要 beta2_arr 已填充。"""
        ...

    @property
    def right_endpoint(self) -> tuple[complex, complex]:
        """(beta1_right, beta2_right) 右端点。需要 beta2_arr 已填充。"""
        ...

    def is_loaded(self) -> bool:
        return self.beta2_arr is not None

    def fill_beta2(self) -> None:
        """通过 get_roots_and_PMGBZ 填充 beta2_arr。"""
        ...


# 类型别名
ConnectedSubset = Union[PointSubset, LineSubset]
```

### 设计要点讨论

**为什么 PointSubset 存 `beta1` 而不是 `mu1, theta1`？**
算法文档中 0D 子集定义为 `(E, beta1, beta2)` 三元组。存储 `beta1`（complex）更直接，且匹配规则中 chordal 距离需要在 beta1 上计算（不是 mu1/theta1）。`mu1` 和 `theta1` 可以通过 property 按需推导。

**为什么 LineSubset 存 `mu1, theta1_start, theta1_end` 而不是 `beta1_start, beta1_end`？**
1D 子集在算法文档中定义为 `(E, mu1, theta1_start, theta1_end, beta2_arr)`。在连续域中，所有点的 `|beta1| = exp(mu1)` 是相同的（固定 mu1），只有 theta1 变化。存储 theta1 的起止范围 + mu1 更准确地反映了这个几何结构。左右端点的 beta1 可以通过 `exp(mu1 + i*theta1)` 推导。

**beta2_arr 的 lazy-load 设计**：
连续域的 beta2 轨迹（sols_arr 中的 M-1 和 M 列）计算量大，且在匹配之前不一定需要。`LineSubset` 创建时不填充 `beta2_arr`，仅在需要时（匹配、端点提取）调用 `fill_beta2()`。

**PointSubset 是 frozen，LineSubset 不是**：
- `PointSubset` 是纯数据，创建后不可变 → frozen=True
- `LineSubset` 有 lazy-load 的 `beta2_arr`，需要在创建后修改 → frozen=False

### GBZ 计算结果容器

```python
@dataclass
class GBZResult:
    """单个 E_ref 的 GBZ 计算结果。"""
    E_ref: complex
    subsets: list[ConnectedSubset]
    index: tuple[int, int]  # (n_0D, n_1D)，空集时为 (0, 0)

    @property
    def is_empty(self) -> bool:
        return len(self.subsets) == 0

    @property
    def is_gbz(self) -> bool:
        """index != (0, 0) 即表示该能量点在 GBZ 内。"""
        return self.index != (0, 0)
```

注意：`index` 只区分 0D 和 1D 两种类型。对于 2D GBZ 问题这就够了。测试中也用 `(0, 0)` vs `(1, 0)` 来区分 GBZ 内/外。

## 实施步骤

### 步骤 1：创建 `gbz_types.py` — 统一数据类 + 公共工具函数

**文件**：`gbz_types.py`（项目顶层，与 `brute_force_amoeba/` 和 `brute_force_SGBZ/` 同级）

**内容**：

1. **数据类**：`PointSubset`, `LineSubset`, `GBZResult`
2. **类型别名**：`ConnectedSubset = Union[PointSubset, LineSubset]`
3. **工具函数**（从 `strip_winding_number.py` 提取，移至此文件）：
   - `chordal_distance(z1, z2) -> float` — 两点在 Riemann 球面上的 chordal 距离
   - `chordal_cost_matrix(arr1, arr2) -> np.ndarray` — 两个根数组之间的 cost matrix
   - `find_cyclic_true_intervals(mask) -> list[tuple[int, int]]` — 循环布尔数组中的连续 True 段
   - `to_sphere_r3(roots) -> np.ndarray` — 复数根映射到 Riemann 球面 R³ 坐标
4. **公共常量**（从两个模块中提取的默认容差值）：
   - 不做——每个模块保持自己的默认值

**关键决策**：这些函数原先在 `strip_winding_number.py` 中是私有函数（`_` 前缀）。提取到 `gbz_types.py` 后去掉下划线前缀，成为公共 API。原文件改为从 `gbz_types` 导入。

### 步骤 2：重构 `brute_force_SGBZ/` — 原生输出统一格式

- **不改动现有 `check_SGBZ`**（生产环境兼容）
- 在 `__init__.py` 中导出新接口

#### 2c. 更新 `__init__.py`

### 步骤 3：重构 `brute_force_amoeba/` — 原生输出统一格式

#### 3a. 修改 `amoeba.py`

- 新增函数 `build_amoeba_gbz_result(amoeba_res, E_ref, char_poly, **kwargs) -> GBZResult`：
  - 离散情况（`is_continuum == False`, `zeros` 非空）：
    - 遍历 `zeros` 中的 `(theta1, theta2)`
    - beta1 = exp(mu1 + i*theta1), beta2 = exp(mu2 + i*theta2)
    - 每个 zero → 一个 `PointSubset`
  - 连续域情况（`is_continuum == True`）：
    - 需要提取连续区间。调用 `get_hungarian_sorted_roots` 获取根轨迹
    - 检测 `|ln|beta2| - mu2| < continuum_tol` 的区间
    - 每个区间 → 一个 `LineSubset`，暂不填充 beta2_arr
  - 空零点情况（`len(zeros) == 0`）：
    - 返回 `GBZResult([], (0, 0))`

- 新增 `collect_GBZ_subsets_unified(coeffs, degs, E_ref, perc, **options) -> GBZResult`：
  - 内部调用现有 `collect_GBZ_subsets`
  - 将结果通过 `build_amoeba_gbz_result` 转换

- **不改动现有 `collect_GBZ_subsets`** 和 `bisect_amoeba_ronkin_min` 等内部函数（生产环境兼容）

#### 3b. 更新 `__init__.py`

添加导出：`collect_GBZ_subsets_unified`, `build_amoeba_gbz_result`

### 步骤 4：处理 Amoeba 连续域数据提取

当前 `collect_GBZ_subsets` 返回的连续域信息不足——只有全局 `is_continuum=True`，没有区间数据。需要补充。

**推荐方案**：在 `build_amoeba_gbz_result` 中实现连续域检测，逻辑如下：

1. 调用 `get_hungarian_sorted_roots(char_poly, E_ref, result["mu1"], N_points)` 获取根轨迹 `tracked` 和 `theta1_arr`
2. 对每个根索引 j，计算 `|ln|tracked[:, j]| - result["mu2"]| < continuum_tol`
3. 用 `find_cyclic_true_intervals` 找出连续 True 段
4. 每个段（长度 ≥ min_continuum_pts）→ 一个 `LineSubset`

这个逻辑本质上是 `_compute_winding_from_tracks` 中已有代码的提取和复用。不需要修改 `amoeba.py` 内部函数，只需在 `build_amoeba_gbz_result` 中重新计算。

**性能考虑**：`get_hungarian_sorted_roots` 已被 `_compute_root_tracks` 缓存。在 `build_amoeba_gbz_result` 中再次调用相当于重复计算。如果后续性能成为瓶颈，可以修改 `collect_GBZ_subsets` 使其返回 root tracks 缓存。但第一步优先保证正确性和接口稳定性。

### 重构前

# SGBZ
res = bfs.check_SGBZ(coeffs, degs, E_ref, perc)

```python
# 统一接口（新增，旧接口保留）
from brute_force_SGBZ import check_SGBZ_unified
from brute_force_amoeba import collect_GBZ_subsets_unified
from gbz_types import PointSubset, LineSubset

# 两者返回相同的类型
gbz: GBZResult = check_SGBZ_unified(coeffs, degs, E_ref, perc)
gbz: GBZResult = collect_GBZ_subsets_unified(coeffs, degs, E_ref, perc)

# 统一消费
for subset in gbz.subsets:
    match subset:
        case PointSubset(E=E, beta1=b1, beta2=b2):
            plot_point(b1, b2)
        case LineSubset(theta1_start=t1, theta1_end=t2):
            subset.fill_beta2()  # lazy load

# index 用于后续拓扑匹配的边比较

    print("Not in GBZ")
```

## 风险与注意事项

1. **工具函数迁移可能影响其他调用者**：需要全局搜索 `_chordal_cost_matrix` 的引用，确保没有其他文件直接使用私有函数（目前仅在 `strip_winding_number.py` 内部使用）
2. **Amoeba 连续域性能**：`build_amoeba_gbz_result` 中重复调用 `get_hungarian_sorted_roots` 会有性能开销。可以在后续优化中将 root tracks 缓存暴露出来
3. **生产环境兼容**：所有现有接口保持不变，仅新增 `_unified` 后缀的并行接口
4. **LineSubset 的 beta2_arr lazy fill**：需要持有 `PolyDiffContext` 引用才能调用 `get_roots_and_PMGBZ`。`LineSubset._poly_diff` 字段存储弱引用还是强引用？建议存强引用——GBZResult 的生命周期内需要它
