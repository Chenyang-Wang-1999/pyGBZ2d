# 拓扑匹配算法说明

## 总体思路
在 `brute_force_amoeba` 与 `brute_force_SGBZ` 中，我们使用暴力法实现了 amoebic GBZ 与 SGBZ 的扫描。
具体算法是给定一个参考能量 `E_ref`，用 `check_amoeba` 或 `check_SGBZ` 去检查这个 `E_ref` 是否在 GBZ 能谱内，如果在，解出所有的 GBZ 点。

现在，我们不仅希望得到 GBZ 的散点，还希望得到 GBZ 的拓扑。这样就需要对原有算法进行改进。好在 `brute_force_amoeba` 与 `brute_force_SGBZ` 的数据结构之间存在共同性。
它们都是对每个参考能量 `E_ref` 给出它对应的 GBZ 点集。点集中可能存在离散的点 (`is_continuum == False`)，或者一维线 (`is_continuum == True`)。
我们可以将 `E_ref` 对应的 GBZ 点集看成是许多个连通子集的集合，然后用一个 label 标注每个连通子集的类别。
对于 2D GBZ 问题，只有两个类别--点或线段。
实际上，旧的数据结构中的 `is_continuum` 就是一种标注。
但为了让代码更加易于维护，还是把所有的数据都抽象为“连通子集”。

拓扑构建的总体思路如下：
1. 先构建能量空间的规格化网格，详见 `demos/replication-ZWang.py`
2. 在网格上用 `check_amoeba` 或 `check_SGBZ` 计算 GBZ 点集，表示成连通子集的 list 的格式。
同时维护一个 tuple，记录每种连通子集的个数，作为该参考能量对应的指标。
如果是空集，那就都是0（需要修改）
3. 对于能量网格的每个边做匹配。若某个边左右两个端点的指标相等（即每种连通子集的个数都一致），那么直接按照每种连通子集的匹配规则相互匹配。反之见4
4. 若能量网格的某一边跨过了不同的 index，那么需要二分找到两种 index 区域的边界点，并且按照每种连通子集的产生-湮灭规则判断是哪几个连通子集发生了变化。同时，对于新产生的边界点，需要新增连线，插入原来的能量网格。

## 连通子集类型与规则
### 0D
对应于旧接口的 `is_continuum == False`, 表示一个孤立点，由 `(E, beta1, beta2)` 三元组表示。
- 匹配规则：将beta1, beta2按chordal距离做匈牙利匹配即可。
- 产生-湮灭规则：成对出现或成对消失

### 1D
对应于旧接口的 `is_continuum == True`，表示一个连续简并的线段，由`(E, mu1, theta1_start, theta1_end, beta2_arr)` 表示。
- 匹配规则：将左端点 chordal 距离 + 右端点 chordal 距离作为cost，做匈牙利匹配
- 产生-湮灭规则：有两种情况
    1. 线段产生/消失：即左右端点碰到一起
    2. 线段分裂/合并：两个线段中的某一个右端点碰到另一个的左端点导致合并，或者一个线段从某个内点分裂成两个线段

## 算法建议
1. 需要重新设计一下旧程序的接口。
2. 初步扫描后，应该先根据每个 `E_ref` 的指标找到跨越边界的连线，再二分找到边界点。注意，插入边界点会改变原有网格的拓扑结构，因此需要更新。相邻边界点之间也要连起来。一般来说，边界点会形成一个闭合回路。
3. 建议从边界点出发向内点做匹配，这样可以持续追踪某个子集从产生到湮灭的全过程。
4. 在实现上，可以分模块实现并测试。除了更新旧程序的接口以外，实际上要做的只有四件事：边界二分查找、边界点的插入、边界处连续子集产生-湮灭类型的判断、内点之间的匹配算法
4. 生产环境中也有`brute_force_amoeba`和`brute_force_SGBZ`这两个库。如果要对这两个库做修改的话，注意测试代码中需要确保你导入的代码是开发环境的。
