# SGBZ 算法梳理

**最后更新**: 2026-08-11（代码审查后）

原来的算法（见 `brute_force_SGBZ`）既难用又不稳定。现在使用 `continuation.ZeroManager` 作为根求解器后端重构算法。模块结构如下：

- `continuum.py`: 连续模相等探测（§1）
- `crossings.py`: 交点探测与求解（§2）
- `winding.py`: 拓扑荷与平均绕数计算（§3）
- `plateau.py`: 零平台检测
- `sgbz_solver.py`: 顶层求解器

先梳理一下整体思路：按照文章（`sn-main.tex`, `sn-supp.tex`）以及旧代码，SGBZ 求解是通过给定一个参考能量 E_ref，求解 E_ref 所对应的 SGBZ subset 来实现的。
SGBZ subset 的求解方式是：首先二分 mu1，（mu1 = ln|beta1|），对于每一个 mu1，可以求解出平均主轴绕数 (average major-axis winding number，旧代码中称作 strip winding number，现弃用)，记作 W(E_ref, mu1)。给定 E_ref 时，W 关于 mu1 单调递增。
依定义，SGBZ subset 需要在 W - mu1 曲线穿过横轴的位置求解。

SGBZ subset 的求解方式如下：给定 E_ref 和 mu1，当 theta1 遍历 [0, 2 * pi]，计算关于 beta2 的多项式方程 char_poly(E_ref, beta1, beta2) == 0 的根，会得到 M + N 个根，其中 -M 与 N 分别是 beta2 在 char_poly 中的最小负幂次和最大正幂次。将 beta2 的根按模长排序，则 subset 由满足 |beta2_M| == |beta2_{M+1}| 的点组成 (注意，每个点是有序对(beta1, beta2)，而不是只有beta2)。对应到 python 的下标，就是 M - 1 和 M (从0开始)

W 的变化与 SGBZ subset 的分布是有关的。当 SGBZ subset 为空集时，W 随 mu1 不变。而当 SGBZ subset 由0维的点构成时，W 随 mu1 连续变化。而当 SGBZ subset 有1维的线时，W 会发生跳变。

W 的定义和性质见 `sn-supp.tex`。求解时，需要充分利用绕数的拓扑等价性。因为数值求解绕数依赖于环绕路径的质量。若环绕路径离零点太近，数值噪声会导致绕数相差 ±1，产生不可忽略的误差。
所以实践中，应该选择**尽可能少的**环绕路径，并利用零点的拓扑荷（见文章）辅助求解其他区域的环路绕数，进而求解平均绕数。
因为绕数在穿过零点的路径上无定义，所以只有零点在 theta2 轴上的投影是一个零测集，平均绕数才有定义。所以，只需要在 subset 只包含0维点时计算绕数。对于1维线，不计算平均绕数，而是对 mu1 做扰动，数值计算 W 在此处的左极限与右极限是否异号，以此判断 W - mu1 曲线是否在此穿过横轴。旧代码中就是这样处理的。

由于探测1维线+0维点要比只探测0维点复杂，所以在二分求解 mu1 阶段和最终求解 SGBZ subset 阶段可以使用复杂度不同的算法。二分阶段只要探测到1维线就提前结束，计算左右极限即可。所以你会看到具体实现函数中，有很多函数都分为”简化版”和”完整版”。

但是，由于数值计算会有离散误差，所以实际计算中有很多细节问题需要处理。现罗列如下：

## 1. 连续模相等探测
`continuation.ZeroManager` 会给出所有根关于 theta1 的函数，并且可以保证每个根关于 theta1 是连续变化的（即不会发生根之间的跳变）。
而复解析性保证只要两个曲线在某一段开集上保持模相等，那么这两个曲线会始终保持模相等，直至左端点和右端点转过 2 * pi重合，或者遇到重根。
对应到 ZeroManager 里，意味着 SegmentData.tracked_roots 中的两列只要有一部分模相等，那么整列都应该保持相等。可以使用类似于 `brute_force_amoeba` 中的投票机制判断。
但是，要注意，这并不意味着 SGBZ subset 中的 LineSubset （1维线）一定会充满 tracked_roots 的一整列，因为根的模长排序会受到其他列的模长变化影响，导致模长相等的两个根不再是 M 和 M + 1。

连续模相等探测也分为简化版和完整版：
- 简化版：将 tracked_roots 中的根按模长排序，判断 index 为 M - 1 与 M 的根是否连续两个点模长相等，且模长关于 theta1 的导数（这个东西是可以解析求解的，见 `continuation/`）也相等。当然这里是浮点数相等，得设置一个容差。要注意 M - 1 与 M 对应的 tracked_roots 列号变化的问题。若检出，则直接返回一个 flag 即可。
- 完整版：在简化版的基础上，收集所有已探测存在模长相等的点在 SegmentData.tracked_roots 的列号，然后用投票机制判断是否涉及的列是整列模相等的。注意，模相等的列可能不只有两个，所以最后返回的是一个 list of clusters，每个 cluster 是一个 tuple[int], 即连续模相等的列在 tracked_roots 中的列号。比如，如果列号为 0, 1, 3 的列模相等，同时 2, 5 两列模相等，那么返回
``` python
[(0, 1, 3), (2, 5)]
```

## 2. 交点探测与求解
因为 ZeroManager 是在离散的网格上求解零点，所以需要额外的交点探测算法来精确求解交点。

先说一下 ZeroManager 的数据格式：ZeroManager 求解零点时，会自动求出路径上所有的重根，并且根据重根的 theta1 值将零点曲线分成多个 segment。重根会标注重根的 index，并且将多个重根吸附在一起。
对于 segment，可以保证前一个 segment 的右端点精确对应后一个 segment 的左端点（即浮点数意义上的 ==）。

### 2.1 探测（用 mu2_mid 收集可疑区间）

虽然 mu2_mid 分段光滑，不能用于全局插值求交，但可以用它来判断哪些区间可能包含交点。对每个子区间 `[θ_i, θ_{i+1}]`，计算 `d[j] = ln|β₂ⱼ| - μ₂_mid`。可疑区间判据：
1. 区间两端 `d[j]` 符号相反
2. 区间两端 `|d[j]|` 均小于某个阈值（可以设得大一点，可以有假阳性，但不能有假阴性）

### 2.2 求交（两两 cubic Hermite + Newton 精修）

对于每个可疑区间，取左右端点 j_lo / j_hi 的**并集**得到候选列号集合 C。C 中的列号两两配对 (a, b)，对每对构建 `f(θ) = ln|β₂_a(θ)| - ln|β₂_b(θ)|` 的 cubic Hermite 差多项式：

- 端点值：`logabs[i,a] - logabs[i,b]` 和 `logabs[i+1,a] - logabs[i+1,b]`
- 端点导数：`Re(V_a) - Re(V_b)`（来自 `seg.tangents`）
- MR 边界或 tangents=None 时用线性 fallback

用 `np.roots` 找根，区间用**左闭右开** `0 <= t < h`：右端点开区间保证与下一个区间无重复。

cubic Hermite 是插值近似而非真值。因此对每个预测交点进行 Newton 精修：

1. `zm.insert_solution(θ_candidate)` → 得到精确根
2. 计算 `f = ln|β₂_a| - ln|β₂_b|`（从精确值）
3. 计算 `f' = Re(V_a) - Re(V_b)`（从精确 tangent）
4. Newton step: `θ_new = θ - f / f'`
5. 重复直到 `|f| < tol` 或步长足够小

### 2.3 去重检测

求解完后，对所有交点两两计算 `|β₁_a − β₁_b|² + |β₂_a − β₂_b|²`。若距离小于阈值则 `raise NotImplementedError` — 目前暂未确定正确的去重策略，先留空占位，等积攒足够测试用例后再处理。

### 2.4 跨 segment 处理

- 左闭右开区间保证跨 segment 边界无重复
- 若无 MR → 常点，不特殊处理
- 若有 MR → 用线性 fallback（`touches_mr`）

交点探测同样是有简化版和完整版两种：
- 简化版：由于简化版的连续模探测步骤会在探测到连续模时提前返回，所以简化版的交点探测中，所有交点都是 0D 交点，因此直接用上述逻辑探测即可。
- 完整版 (TODO)：完整版的交点探测有两个任务：一是找到所有 0D 交点，二是找到所有 1D 子集的边界。对于连续模相等的情况，数值噪声会误触上述交点探测算法，产生假阳性。因此，对于每个连续模相等的 cluster，需要取一个代表元，这样就避免误触求交算法了。
但是，此时要注意，寻找 index 为 M 与 M - 1 的曲线时，要计入每个 cluster 的重数。
    - 首先：先找到连续模相等的区间。有了代表元之后，只需判断 M - 1 和 M 对应的 cluster index 是否相等即可。例如，在row_idx = 0, 1, 2, ..., k 时，cluster index 保持相等，但在 row_idx = k + 1，M - 1 对应的 cluster index 发生变化，那就说明 1D subset 的右端点位于 row_idx = k 与 k + 1 的这个区间上。此时使用上述求交算法，求出原来的代表元曲线和新的 M - 1 对应的代表元曲线在该区间上模长交点，即可定出 1D subset 的右端点。左端点同理。
    - 然后：在没有连续模相等的部分，复用简化版的探测逻辑。

## 3. 拓扑荷与主轴平均绕数计算
关于零点的拓扑荷可以参考 `sn-supp.tex`。这里简述判断标准。

首先，拓扑荷只需要在简化版中计算，完整版反而不用求拓扑荷。因为这个东西只对主轴平均绕数计算有用。
同样地，拓扑荷只对 0D 点集有良定义。数值上，它等于 theta2 从左到右跨过这个零点时，环路绕数的变化值。

对于常点，即 *斜穿过 mu2_mid 的点*，拓扑荷可以根据其穿过 mu2_mid 的方向判断。当 theta1 增大时，零点曲线由下向上穿过 mu2_mid，则拓扑荷为 +1，反之为 -1。

对于重根或者切触，情况要更复杂一些。但在我们的求解程序中，一般很难会遇到切触。更多的情况是数值误差使得切点变成交点——这对于我们的程序来说反而更稳定。切触的拓扑荷一般为0，因为切触点的拓扑结构没有改变。
而重根的拓扑荷需要一个环绕重根的小环路去计算，而这样做的话数值误差会非常大。所以对于重根或切触，我们干脆就不计算拓扑荷了，而是在主轴绕数计算步骤中用它们去划分计算区。

关于主轴平均绕数的计算，按照定义，它是一系列环路绕数的均值。环路按照以下方式定义：保持 mu1 和 theta2 不变，让 theta1 环绕 2 * pi，同时 mu2 —— 也就是 ln|beta2|，取 mu2_mid。注意，这个数是 theta1 的函数，而且它是分段光滑的。
旧代码中使用的是全局三次样条插值，虽然暂时没出错，但这个算法是不安全的。应该放弃插值，直接用计算数据点去用折线段代替曲线段。这样反而会更安全。

实际计算中，我们不要计算所有曲线的绕数，而是充分利用上文提到的拓扑荷，尽量减少环路绕数计算。例如，对于没有重根的情况（如下图，'+'是拓扑荷 +1, 'x' 是拓扑荷-1）
``` ascii
2π ┌───────────────────────────────────────────┐
   │     |  |                   |   |          │
   │     +  |                   x   |          │
θ1 │  A  | B|         C         | D |          │
   │     |  x                   |   +          │
   │     |  |                   |   |          │
 0 └───────────────────────────────────────────┘
   0                     θ2                    2π
```
例如，如果我在 C 区计算的环路绕数为 w0, 那么在 D 区就是 w0 - 1，A 区就是 w0，B 区就是 w0 + 1。
所以我只要在这几个区域中任选一个位置计算环路绕数即可，计算次数为1。
为了计算的鲁棒性，可以在整个 theta2 区间中取多条曲线，计算哪条曲线离零点的距离最远，取最远的那条曲线。这样就可以避免数值误差导致绕数出现 ±1 错误。

对于存在重根或切触的情况，要更复杂一些。例如下图中，o表示重根或切触：

``` ascii
2π ┌───────────────────────────────────────────┐
   │     |  |         |         |   |    |     │
   │     +  |         |         x   |    |     │
θ1 │  A  | B|    C    o    D    | E | F  o     │
   │     |  x         |         |   +    |     │
   │     |  |         |         |   |    |     │
 0 └───────────────────────────────────────────┘
   0                     θ2                    2π
```

因为重根或切触的拓扑荷未知，我们无法通过 "o" 左边的环路绕数去推测 "o" 右边的。因此，例如上图中，我们需要至少计算两次环路绕数：一次在 A, B, C 三者之一，另一次在 D, E, F 三者之一。

## 4. 实现细节与代码审查要点

### 4.1 交点探测的两阶段批处理

`crossings.py` 中的 `_find_crossings_in_interval` 采用两阶段算法：

1. **快照阶段**：在 Newton 插入之前，对所有候选列对构建 cubic Hermite 多项式
2. **精修阶段**：批量执行 Newton 精修

这样做的原因：Newton 精修会调用 `zm.insert_solution`，该函数会修改 `SegmentData.tracked_roots`。如果在遍历列对的过程中逐个精修，后续列对的 cubic 构建会读取到已被修改的数据，导致错误的端点值。

**关键代码** (`crossings.py:313-346`)：
```python
# Phase 1: 快照端点，构建所有 cubic
logabs_i = logabs[i]
logabs_ip1 = logabs[i + 1]
tangent_i = seg.tangents[i] if seg.tangents is not None else None
tangent_ip1 = seg.tangents[i + 1] if seg.tangents is not None else None

predictions = []
for a, b in pairs:
    c_diff = _build_pair_cubic_from_snapshot(...)
    predictions.extend(...)

# Phase 2: Newton 精修
for theta_pred, a, b in predictions:
    _newton_refine(...)
```

### 4.2 平台检测的聚类前检查

`plateau.py` 中的 `_check_pmgbz_points_clustered` 使用 **(θ₁, θ₂) 环面上的欧氏距离**判断点是否聚集：

```python
# 对每个点，检查是否存在邻居在容差范围内
d1 = _circ_dist(t1_i, t1_j)
d2 = _circ_dist(t2_i, t2_j)
d = sqrt(d1² + d2²)  # 欧氏距离
if d < tol_rad:
    has_neighbor = True
```

**重要**：必须同时考虑 θ₁ 和 θ₂，而不是只看 θ₁。原因是：

- 同一 θ₁ 处可以有多个不同的 β₂（简并对）
- 只看 θ₁ 会将这些简并对误判为"聚集"
- 实际上它们在 (β₁, β₂) 空间中是分离的点

例如，gain-loss Haldane 模型在 E=0.5 处有 6 个点，分为 3 对简并对：
- θ₁ = 163.3°：两个点，θ₂ 分别为 196.7° 和 0°
- θ₁ = 0°：两个点，θ₂ 分别为 196.7° 和 163.3°
- θ₁ = 196.7°：两个点，θ₂ 分别为 163.3° 和 360°

这些点在 (θ₁, θ₂) 环面上的最小距离约 33°，远大于容差 3.6°，因此正确判定为"非聚集"，跳过平台检测。

### 4.4 bisection 收敛条件

当 `w_mid` 为 `None`（continuum 非边界）时，不应检查收敛：

```python
if w_mid is None:
    f_mid = proxy_w  # 使用左极限作为代理
else:
    f_mid = w_mid
    # 只在真实 winding 值处检查收敛
    if abs(f_mid) <= zero_tol or (mu1_high - mu1_low) < xtol:
        return ...
```

原因是：continuum 点的 W 无定义，使用代理值判断收敛会混淆"左极限为零"与"W 为零"。
